# Summary of the Language Model System

This system is a Telegram-based AI chatbot that efficiently manages multiple language models while optimizing token usage through a sophisticated workflow. Here's a clear breakdown:

## Core Architecture
- **Database**: Tracks models, scores, message history, queue, and user settings
- **RAG (Retrieval-Augmented Generation)**: Handles document retrieval and context storage
- **LangGraph**: The state machine that processes messages through a defined workflow
- **Telegram Bot**: The user interface for message interactions

## Key Workflow Stages
1. **Message Reception**: User sends message → system checks blacklist status
2. **Message Processing**: 
   - Cleans message (removes emojis/symbols)
   - Translates to English
   - Stores in history and RAG
3. **Role Selection**: 
   - Determines optimal role for message
   - Validates role with scoring (iterative process)
4. **Response Generation**:
   - Uses top N models (with periodic full scoring)
   - Selects best-performing model
   - Generates and saves response
5. **Proactive Engagement**: 
   - Detects user inactivity (≥ random time window)
   - Automatically switches to "AGITATOR" role to encourage engagement

## Token Optimization Strategy
- **Per-user**: Fixes best-performing model for each user session
- **Global**: Full model scoring occurs every `FULL_SCORING_INTERVAL` messages
- **Efficiency**: Uses only top N active models (typically 50) with minimal full scoring
- **Result**: Significant token savings while maintaining high-quality responses

## Special Features
- **Proactive Behavior**: Automatically triggers engagement when users become inactive
- **Error Handling**: Comprehensive logging and retry mechanisms
- **Model Management**: Tracks model performance metrics and updates settings
- **UI Integration**: Web interface for controlling settings (clean messages, blacklists, etc.)

## Implementation Notes
- Runs as an asynchronous system (using `asyncio`)
- Requires Telegram bot token in `.env` file
- Uses Pinecone or Qdrant for vector storage
- Designed for production deployment with minimal token costs
- Includes comprehensive logging to `bot_system.log`

This system effectively balances model performance with cost efficiency, making it suitable for real-world applications where both quality and token economy are critical concerns.
