### 🌟 **System Overview**  
A **turnkey asynchronous language bot** that:  
✅ Processes messages end-to-end via LangGraph workflows  
✅ Dynamically manages up to 50 LLMs with real token economy  
✅ Combines proactive user engagement (e.g., "AGITATOR" role for inactivity) with precise scoring  
✅ Supports real-time Telegram integration with UI-based administration  

---

### 🔑 **Core Components & Flow**  
| **Layer**               | **Key Function**                                                                 | **Technical Highlight**                                  |
|-------------------------|--------------------------------------------------------------------------------|----------------------------------------------------------|
| **1. Foundation**       | Database initialization, model storage, RAG setup                              | `db.init_tables()` → Creates tables for models, history, queuing |
| **2. Message Pipeline** | Telegram → Cleanup → Translation → Role Judgement → Response gen.               | Async-safe via `app.ainvoke()` with *proactive check* for inactive users |
| **3. Intelligence**     | Context retrieval (RAG), model scoring, session-specific model caching          | **Top N models** + **full scoring** every `FULL_SCORING_INTERVAL` messages |
| **4. Admin**            | UI control over blacklist, model switching, session resets, pausing             | UI runs in dedicated thread to avoid blocking main loop |

---

### ⚙️ **Critical Workflows**  
#### **1. Model Selection Optimization**  
- **Per-user session**: Fixes top model (e.g., `fixed_llm_@user`) after validation  
- **Global rotation**: Runs full scoring (all active LLMs) **only once every 50 messages** → *critical token savings*  
- **Real-time update**: `global_message_count` tracks rotation intervals

#### **2. Proactive Engagement**  
When user inactive > `RANDOM_INACTIVITY_PERIOD` (1-3 min):  
→ Automatically triggers *"AGITATOR" role* → sends provocation message  
*(Example: "What if... [thought-provoking question]?" to restart engagement)*

#### **3. Error Resilience**  
- Failsafes: Message retry without queue deletion (if error during processing)  
- Detailed logs: `bot_system.log` tracks all LLM calls and RAG operations

### 💡 **Why This Design Works**  
1. **Cost-effective**: Only `N+1` LLMs active per message (vs. full 50 all the time)  
2. **Proactive UX**: Avoids user abandonment via smart inactivity detection  
3. **Admin-friendly**: UI controls bypass backend complexity  
4. **LangGraph elegance**: Conditional rejudgements (`RESCORE`) and parallel processing ensure stability  

> ✅ **Real-world example**: When user `@inactive_123` hasn’t spoken in 2.5 min → Bot switches to *AGITATOR role* → sends: *"Is your AI thinking? Try: 'If I said "no" earlier, what would I want?' - Type 'help' to reset."*

### 📚 **Troubleshooting Tip**  
If a message gets stuck:  
1. Check `bot_system.log` for: `ERROR: Failed at [node name]`  
2. Run: `await db.get_setting("last_error")` → resolves common RAG/connection issues
