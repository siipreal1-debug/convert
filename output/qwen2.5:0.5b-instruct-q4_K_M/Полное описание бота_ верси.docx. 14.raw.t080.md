Конечно! Вот общий план работы программы:

1. **Запуск программы**:
   - Создаётся объект базы данных `db`, отсылаемённый `Database()`.
   - Создается UI, отсылаемённый `UI(db)`.

2. **Инициализация в main()**:
   - Запускается асинхронный цикл (`asyncio.run(main())`).
   - Создаётся объект `db`, устанавливает таблицы.
   - Создается объект `rag`, загружает эмбеддер и подключает к Pinecone/Qdrant.

3. **Обработка в графе LangGraph**:
   - Станит обработка нод с моделью `llm`.
     - `translate_message` — очищение (если clean_messages), перевод (translator.translate_to_english(clean_msg)), сохранение истории (`await db.add_history(...)`) и упаковка в state.
     - `judge_role` — выбирает роль модели, обновляет last_activity.
     - `validate_role` — выбирает модель с помощью LLM-вызовов.
     - `retrieve_ r_a_g` — подходит к `generate_response`.
   - Обрабатывает ноды с `llm` и `rag`:
     - `judge_role` — выбирает модель с помощью LLM-вызовов.
     - `validate_role` — выбирает модель с помощью LLM-вызовов.
     - `retrieve_ r_a_g` — подходит к `generate_response`.
   - Обрабатывает ноды с истории:
     - `judge_role` — выбирает роль модели с помощью LLM-вызовов.
     - `validate_role` — выбирает модель с помощью LLM-вызовов.
     - `retrieve_ r_a_g` — подходит к `generate_response`.
   - Обрабатывает ноды с проверкой роли:
     - `judge_role` — выбирает роль модели, обновляет модель.
     - `validate_role` — выбирает модель с помощью LLM-вызовов.
     - `retrieve_ r_a_g` — подходит к `generate_response`.
   - Обрабатывает ноды с логированием и сохранением:
     - `log_and_save` — записывает обработанное в окошки.

4. **Обработка в графе LangGraph**:
   - Проверяет роль модели (`judge_role`).
   - Добавляет информацию о модели в `history`.

5. **Проактивные действия (в proactive_check)**:
   - Клавиши `check_inactivity`, `clear_llm_cache`.
   - Меняет ролей на "AGITATOR" для всех локализованных LLM, если в диапазоне сессий.

6. **Сессии и экономия**:
   - Включает в себя ограничение по количеству LLM в сессии.
   - Полный скоринг раз в FULL_SCORING_INTERVAL сообщений.
   - Использует глобальное `last_activity`.

7. **UI-методы (в классе UI)**:
   - `set_clean`: Меняет clean_messages.
   - `add_blacklist`: Обновляет чат-ботов.
   - `set_operator`: История обновляется после каждого скоринга.
   - `toggle_pause`: Заменяет paused на "AGITATOR".
   - `reset_sessions`: Удаляет локализованные модели из истории.

### Основные моменты:

- **Асинхронность**: Обработка цикла асинхронно, а также обработка логов и сохранения.
- **История**: Добавлено истории модели в `history`.
- **Регулярные задачи**: Управление чатами, логированием и управлением активностью LLM.

Этот план позволяет программировать бесконечный бесконечный процесс обработки сообщений через асинхронный код, что делает его более продвинутым для упрощения и снижения использования токена.
