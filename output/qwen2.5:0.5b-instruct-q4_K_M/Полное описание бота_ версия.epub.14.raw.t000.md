Конечно! Вот обзор основных шагов и процесса работы бота:

1. **Запуск программы (main_flow.py)**:
   - Создает объект базы данных `db`.
   - Создает UI-окно с текстами и кнопками.
   - Запускается асинхронный цикл: `asyncio.run(main())`.

2. **Инициализация в main()**:
   - Инициализирует библиотеку `Database` для работы с базой данных.
   - Создает UI-окно с текстами и кнопками.
   - Запускается асинхронный цикл: `asyncio.run(main())`.

3. **Чтение сообщений из Telegram**:
   - Получает update (сообщение).
   - Извлекает user, message, chat_id.
   - Если пользователь в чёрном списке (`db.is_blacklisted(user)`), игнорирует.
   - Добавляет в UI: `ui.add_incoming(user, message)`.
   - Если пауза (paused):
     - Записывает сообщение в очередь: `item = await db.get_queue_item()`.
     - Если есть:
       - Создает state с user, message, chat_id.
       - Обрабатывает: `app.ainvoke(state)` — проходит граф (ноды ниже).
       - После: `response = result['response']`.
       - Отправляет: `application.bot.send_message(chat_id=chat_id, text=response)`.
     - Если ошибка:
       - Записывает сообщение в историю: `log_error(e, context)` и не удаляет.
       - Если очереди нет: `await asyncio.sleep(1)`.
       - Если очереди нет:
         - Инициализирует состояние: `state = state or {'user': user, 'message': message, 'chat_id': chat_id}`.

4. **Обработка в графе LangGraph**:
   - `translate_message`: Очищает (если clean_messages), переводит (\`translator.translate_to_english(clean_msg)\) и сохраняет в history (\`await db.add_history(...)`).
   - `judge_role`: Выбирает роль: `await llm.determine_role(translated_message, default_model)`.
   - `validate_role`: Проверяет: `await llm.get_valid_role_score(role, translated_message)`, если $<$ порога — role = "RESCORE".
   - `retrieve_rag`: Ищет контекст и upsert translated_message.
   - `select_llm`: `fixed_llm = await db.get_setting(f"fixed_llm_{user}")`.
     - Если count $\%$ FULL_SCORING_INTERVAL $= 0$ — models = все active_llms (полный скоринг).
     - Иначе топ- $\bar { \mathbf { N } + \mathbf { \Xi } }$ outsider.
   - `proactive_check`: Если неактивность (check_inactivity) — роль "AGITATOR".
   - `generate_response`: Генерирует parallel: `await llm.generate_responses_parallel(...)` и выбирает best, фиксирует (\`await db.set_setting(f"fixed_llm_{user}", best_model)\`), сохраняет в history и rag, обновляет average_score (\`await db.set_model_score(user, best_model, score)\) и сохраняет в history.

5. **Проактивные действия (in proactive_check)**:
   - Глобальная last_activity обновляется при сообщениях.
   - Если time.time() $>$ last_activity + random (INACTIVITY_MIN-MAX мин $\ast 6 0$) — меняет роль на "AGITATOR", сообщение на провокацию.

6. **Сессии и экономия**:
   - Фиксирует лучшую модель на сессию: `fixed_llm_{user}`.
   - Полный скоринг раз в FULL_SCORING_INTERVAL сообщений (глобально, не per user).

7. **Логирование и сохранение**:
   - Ошибки: `log_error(e, context)`.
   - LLM-вызовы: `await db.log_llm_call(...)` и `await db.add_history(...)`.
   - История: `await db.add_history(...)`.
   - RAG: `await db.set_model_score(...)` с полными metadata.

8. **UI-методы (in UI)**:
   - set_clean: Меняет clean_messages.
   - add_blacklist: `db.set_setting("blacklist_{user}", True)`.
   - set_operator: `db.set_setting("operator", value)`.
   - toggle_pause: Переключает paused.
   - reset_sessions: Удаляет fixed_llm_\*.

Этот процесс позволяет боту работать с пользователями в асинхронном режиме, экономя токены и уменьшая нагрузку на сервер.
