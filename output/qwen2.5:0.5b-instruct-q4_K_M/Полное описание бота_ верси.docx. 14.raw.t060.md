Конечно! Вот общее описание основной работы системы:

1. **Запуск программы**: Главная функция — создание базы данных и UI.

2. **Инициализация**: Создает объект базы данных `db`, загружает модель OpenRouter API, устанавливает статус обработки сообщений в UI.

3. **Чтение сообщений из Telegram**: Получает сообщение, идёт проверка пользователя на чёрные списки и обработка сообщения.

4. **Основной цикл обработки в main()**:
   - Сбрасывает все активные модели.
   - Запускает графику LLM-обмена (translate_message, judge_role, validate_role).
   - Обрабатывает сообщение и отправляет ответ на UI.
   - Если ошибок — обрабатывает логи и сохраняет историю.

5. **Обработка в графе LangGraph**:
   - Обрабатывает команды `judge_role`, `translate_message` и `retrieve_ r a g`.
   - Проверяет роли, выбирает лучшую модель на сессию и обрабатывает её.
   - Сохраняет историю сообщений и модели.

6. **Проактивные действия**:
   - Обновляет статус сессии и логирование.
   - Закрывает UI-контейнер, если игрок активирован.

7. **UI-методы**:
   - Меняет состояние сообщений.
   - Добавляет текстовые сообщения в `ui`.
   - Обрабатывает команды `set_clean`, `add_blacklist`, `set_operator` и `toggle_pause`.

### Примечания:
- Важно убедиться, что модели OpenRouter API и RAG находятся на портфеле.
- Для запуска программы с ошибками — можно использовать `--log-level=error` для использования логов debug.

Эта система позволяет обрабатывать сообщения в реальном времени, используя асинхронные операции и экономичное использование токенов.
