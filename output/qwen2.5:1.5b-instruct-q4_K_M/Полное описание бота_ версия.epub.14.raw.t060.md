Система "бота" для обработки сообщений имеет следующий порядок выполнения:

### 1. Запуск программы (в файле `main_flow.py`, блок `if __name__ == "__main__"`)

- Создается базовая структура данных:
  - База данных: создается объект `db` и выполняется методы для создания таблиц (`init_tables()`).
  - Регулярный ресурс: создается объект `rag` для управления эмбеддером и подключения к Pinecone/Qdrant.
  - Объект для обработки запросов: создается `llm` на основе базы данных и объекта `rag`.
- Создается интерфейс (UI) в виде окна с текстами и кнопками:
  ```python
  ui = UI(db)
  ```
- UI запускается в отдельном потоке, чтобы не блокировать основной цикл программы.
- Асинхронный цикл запускается:
  ```python
  asyncio.run(main())
  ```

### 2. Инициализация в `main()` (асинхронно)

- Создаются необходимые объекты для базы данных, регулярных ресурсов и ЛLM:
  - База данных: создается объект `db` и выполняются методы для создания таблиц (`init_tables()`).
  - Регулярный ресурс: создается объект `rag` для управления эмбеддером и подключения к Pinecone/Qdrant.
  - Объект для обработки запросов: создается `llm` на основе базы данных и объекта `rag`.
- Загружены модели ЛМ:
  ```python
  models = fetch_free_llms()
  ```
- Сохраняются активные модели в базе данных:
  ```python
  await db.set_free_llms(models)
```

### 3. Чтение сообщений из Telegram (функция `telegram_handler`, асинхронно)

- Получает update (сообщение).
- Извлекает user (username), message (текст), chat_id.
- Если user в чёрном списке, игнорирует.
- Добавляет в UI: `ui.add_incoming(user, message)`.
- Если пауза (paused): сохраняет сообщение и не обрабатывает.
- Иначе:
  - Очищает текст, если чистим (если `clean_messages`).
  - Добавляет в очередь: `await db.add_to_queue(user, message, chat_id)`.

### 4. Обработка в графе LangGraph (функции `ainvoke`, асинхронно)

- \*\*translate\_message\*\*: очистка текста и перевода, сохранение в истории и редактирование metadata.
- \*\*judge\_role\*\*: вычисление роли по модели ЛМ с параметрами по умолчанию.
- \*\*validate\_role\*\*: проверка роли на основе множественных судей (если роль не удовлетворяет порогу - изменяется на "RESCORE").
- Conditional needs\_rejudge: если "RESCORE" — возвращается к функции `judge_role`, иначе возвращается к функции `retrieve\_rag`.
- \*\*retrieve\_rag\*\*: поиск контекста по редактированному сообщению.
- \*\*select\_llm\*\*: выбор модели ЛМ на основе параметров:
  - Если "fixed_llm_{user}" - использует модель, вычисленную в базе данных.
  - Иначе: выбирает моделей из списка активных моделей или топ N моделей с максимальным количеством сообщений (полный скоринг).
- \*\*proactive\_check\*\*: проверка последней активности пользователя, если она превышает определенное время — изменяется роль на "AGITATOR".
- Conditional is\_proactive: всегда вызов функции `generate_response`.
- \*\*generate\_response\*\*: генерация ответов в параллелях, оценка скоринга и выбор лучшей модели.
  - Фиксация лучшего варианта на сессию (например, "fixed_llm_{user}").
  - Обновление информации в базе данных для истории и регулярного ресурса.
- \*\*log\_and\_save\*\*: запись логов, сохранение ЛМ-вызовов и истории.

### 5. Проактивные действия (в функции `proactive_check`)

- Глобальная последняя активность обновляется при новых сообщениях.
- Если время превышает определенное значение (например, случайное число в диапазоне от 60 до 120 минут), изменяет роль на "AGITATOR" и сбрасывает текст на провокацию.

### 6. Сессии и экономия (в функциях `select_llm` и `generate_response`)

- Фиксирует лучшую модель на сессию (например, "fixed_llm_{user}").
- Полный скоринг раз в определенное время (например, FULL\_SCORING\_INTERVAL сообщений).
- Удаляет информацию о сессии после завершения выполнения.

### 7. Логирование и сохранение

- Ошибки: логирование ошибок (`log_error`, `context`).
- Запись в базу данных: добавление истории, модели ЛМ, логирования вычислений.
- Сохранение редактированного текста в регулярном ресурсе.

### 8. UI-методы (в классе `UI`)

- Помещает информацию в окно и обрабатывает запросы:
  - Обработка кнопок для изменения состояния паузы, добавления или удаления чёрного списка, установки оператора и т.д.

### Система асинхронная (asyncio) с экономией токенов, поддерживает до 50 моделей ЛМ и обеспечивает обработку сообщений по очереди, сохраняя последние активности пользователей для определения их роли в зависимости от контекста.
