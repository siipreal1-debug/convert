### Описание системы

#### Запуск программы
1. **Запуск программы**:
   - Создается база данных (`db`).
   - Создается UI (управление окномами) и запускается в отдельном потоке.
   - Асинхронный цикл запускается.

2. **Инициализация в main()**:
   - Загружается список доступных моделей (`models`).
   - Сохраняются все доступные модели (`db.set_free_llms(models)`).
   - Создается граф (LangGraph) для обработки сообщений.
   
3. **Чтение сообщений из Telegram**:
   - Получает и обрабатывает каждое сообщение.
   - Извлекает информацию о пользователе, сообщении и чате ID.
   - Если пользователь в черном списке — игнорирует сообщение.
   - Добавляет полученное сообщение в UI.

4. **Основной цикл обработки**:
   - Используется асинхронный цикл для обработки сообщений из очереди.
   - Если пауза активна, просто пропускает.
   - Обрабатывается каждое состояние графа (`translate_message`, `judge_role`, и т.д.).
   - После обработки отправляется ответ в чат.

5. **Обработка в графе LangGraph**:
   - Действия по переводу сообщения (`translate_message`), определению роли (`judge_role`), проверке роли (`validate_role`), получении контекста (`retrieve_rag`) и выбору модели для скоринга (`select_llm`).
   - Проактивные действия в случае неактивности (`proactive_check`).

6. **Сессии и экономия**:
   - Фиксируются лучшие модели на сессию (`fixed_llm_{user}`) при определенных условиях.
   - Полный скоринг раз в `FULL_SCORING_INTERVAL` сообщений.

7. **Логирование и сохранение данных**:
   - Логи ошибок записываются в файл (`log_error(e, context)`).
   - Запись LLM-вызовов в базу данных (`db.log_llm_call(...)`).
   - Сохранение истории сообщений и контекста в репозитории (`db.add_history(...)`, `rag.upsert(...)`, `db.set_model_score(...)`).

### Примеры действий
1. **Обработка перевода**:
   ```python
   await translate_message(message)
   ```

2. **Определение роли**:
   ```python
   role = await judge_role(translated_message, default_model)
   ```

3. **Проверка роли**:
   ```python
   score = await validate_role(role, translated_message)
   if score < ROLE_SCORE_THRESHOLD:
       role = "RESCORE"
   ```

4. **Выбор модели для скоринга**:
   ```python
   models = await select_llm(user=user)
   best_model = ...
   ```

5. **Проактивные действия (например, если неактивность) в `proactive_check`**:
   ```python
   if not user.is_active:
       await reset_sessions()
   ```

6. **Сессии и экономия**:
   ```python
   fixed_llm = db.get_setting(f"fixed_llm_{user}")
   if fixed_llm is None or fixed_llm != best_model:
       await set_setting("fixed_llm_{user}", best_model)
       await db.set_model_score(user, best_model, score)
   ```

### Вывод
Система обрабатывает сообщения асинхронно, использует базу данных для хранения истории и распределение моделей, экономит токены с помощью полного скоринга и проактивных действий, что обеспечивает эффективную работу даже в сложных ситуациях.
