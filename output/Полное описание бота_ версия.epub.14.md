Это детальное описание бота на основе Telegram, который использует искусственный интеллект (LLM) для обработки и ответа сообщений пользователей. Система состоит из нескольких ключевых компонентов:

1. **Тelegram-бот**: Это основная часть, которая слушает сообщения в Telegram через библиотеку python-telegram-bot. Он проверяет пользователя на черный список и добавляет сообщения в очередь для обработки.

2. **Очередь сообщений**: Это асинхронная система, использующая библиотеку aiosqlite для управления сообщениями в очереди. Она обеспечивает последовательное обработку сообщений.

3. **Граф обработки сообщений**: Это структура шагов (flowchart), которая проходит через процесс обработки каждого сообщения — очистка, выбор роли, проверка на активность, генерация ответа и т.д. Граф использует состояния для сохранения точки входа между шагами.

4. **Менеджер LLM**: Это класс, который общается с сервисом OpenRouter асинхронно для вызова моделей LLM. Он также отвечает за определение роли и оценку качества ответов.

5. **RAG-менеджер (SentenceTransformer)**: Это векторная база данных, которая сохраняет сообщения и ответы в виде эмбеддингов. Он используется для поиска похожих записей на основе nick_name или namespace.

6. **База данных SQLite**: Эта часть хранит все модели, скоринги, историю, логи и настройки. Она обеспечивает асинхронные операции для обновления среднего скоррелята моделей и других действий.

7. **Интерфейс пользователя (UI)**: Это Tkinter-интерфейс, который показывает логи, входящие сообщения и ответы. Он также включает кнопки для очистки сообщений, добавления пользователей в черный список, установки оператора и сброса сессий.

8. **Дополнительные модули**: Это утилита для обработки документов, которая загружает репозиторий Git, проверяет последний коммит и процессоры документов.

Запуск бота включает в себя создание объектов базы данных и UI, а затем запуск асинхронного цикла. В основном цикле выполняются следующие шаги:

1. **Инициализация**: Создается объект базы данных и RAG-менеджер, а также создаются таблицы в базе данных.
2. **Асинхронный цикл**: Он продолжает обрабатывать сообщения из очереди, используя вышеуказанные компоненты для обработки и ответа каждого сообщения.

Система работает асинхронно, чтобы не задерживать обработку одного сообщения другим. Каждое сообщение проходит через процесс шаг за шагом в графе обработки сообщений и LLM менеджер, затем используется RAG-менеджер для поиска похожих записей или модели, а затем ответа генерируется и сохраняется в базе данных. UI отображает логи и результаты в реальном времени.
