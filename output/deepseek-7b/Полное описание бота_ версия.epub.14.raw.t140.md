В предоставленном коде описывается разработка синхронного бота для Telegram, который используется для обработки сообщений с использованием Large Language Models (LLM). Следующий пошritt-by-step разбор:

### 1. **Общая логика работы бота**

- **Основное событие**: `main()`, которое вызывает асинхронный цикл обработки сообщений.
- **Архитектура**:
  - База данных (`Database`) для хранения смен, скорингов, истории и других параметров.
  - Бот-.Restricted API (`RAGManager`) для взаимодействия с Pinecone или Qdrant для контекста.
  - Логирование (`logger`), локализация (`Translator`).
  - Graph обработки (`LangGraph`) для последовательной или有条件ной обработки сообщений.

### 2. **Этапы работы бота**

1. **Загрузка моделей**:
   - Попросить у пользователя фиксированную модель через `UI.add_blacklist(user)` если user в чёрном списке.
   - Проверить, неактивен ли bot: через `check_inactivity`.
   
2. **Работа с сообщениями**:
   - Если бот неактивен, отвечает на сообщение.
   - Снижение активности с помощью `UI.set_clean()` или добавление в чёрный список.

### 3. **Этапы обработки сообщений**

1. **Translation**:
   - Очищает текст ( если clean_messages) и переводит с русского на английский.
   
2. **Role Selection**:
   - Проверяет персональныели ( personal models ) для определения роли.

3. **Validation of Role**:
   - Проверяет персональные модели, чтобы выбрать лучший вариант.

4. **Retrieve RAG**:
   - Ищет контекст в репозитории контекстов (`RagManager`).

5. **Select Model/Language**:
   - Выбирает лучшую модель или язык для обработки сообщения.

6. **Proactive Check**:
   - Проверяет, неактивна ли last_activity и, если да —切换 user角色.

7. **Generation of Response**:
   -Generates response using selected model and sends back as a message.
   
### 4. **Сессии (Session Management)**

- **Fixed LLM Selection**: Следует фиксированному персональному моделю или полным резервированию (global count).
- **Proactive Scoring Check**: Проверяет время активности и переключает между фиксированным mods.

### 5. **日志 и локализация**

- **Log Messages**:
   - Логирует об ошибках LLM, контекстах, результатах резервного обмена.

### Заключение

Этот бот демонстрирует гибкость в обработке асинхронных сообщений с использованием Large Language Models. Основными особенностями являются адаптивное выборение моделей, резервное общение и эффективное управление заходами для минимизации токены.
