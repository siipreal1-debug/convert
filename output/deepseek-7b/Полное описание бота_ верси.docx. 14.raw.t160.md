Для понимания работы системы обработки сообщений (美感系统) можно разделить её на основные модули и их функции. Ниже представлен подробный объяснение каждого этапа:

---

### 1. **Основы системы**
- **Токанг (Telegram API)**: Используется для отправки сообщений, обработки Telegram-подключений и обработки ошибок.
- **Aiohttp**: Для работы с external API (например, OpenRouter для LLM).
- **Database (База данных)**: Завершающаяся база данных для хранения историй, last_activity, last scoring и других基本信息 о пользователях.
- **RAG (Retrieval-Augmented Generation)**: Используется с Pinecone или Qdrant для работы с контекстом.
- **LLMManager**: Управляет доступными LLM-моделями и их Scorings.

### 3. **Внутренние методы TelegramHandler**
- **telegram_handler(update)**:
  - Пars message, user, chat_id из update.
  - Если user чёрный, пропускает.
  - Устанавливает clean_message.
  - Обновляет в DB last_activity и в RAG.
  - Проверяет, нужно ли прогнать graph again.

### 4. **Приоритетные этапы**
1. **Инициализация баз данных**.

4. **Проведение async- main() цикла**.

---

### 5. **Функции логирования и сохранения**
- **db.log_llm_call()**: Логирует информацию о LLM- phone call.
- **db.add_history_and_rating()**: Добавляет в историю LLM's ответы с рейтинами.
- **set_last_activity**: Обновляет last_activity для пользователя.

---

### 6. **Рекомендации по оптимизации**
1. **Инициализировать RAG periodically**: При random check (proactive_check).
2. **Сбрасывать fixed_llm_{user}**: При global FULL_SCORING_INTERVAL.
3. **Убедиться, что база данных поддерживает large-scale queries**.
4. **Проверить работу с пользователями**: Передавайте Usernames в чёрный список если他们是 администраторы.
