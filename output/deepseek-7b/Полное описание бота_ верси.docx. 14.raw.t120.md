Данная система обработки сообщений для Telegram very-версия реализована на основе asyncio и async-функций. Она обеспечивает эффективное обработку данных с использованием графа обработки (LangGraph), который включает этапы очистки, перевода, выбора роли,检索 контекста и генерации ответов. Система employs async-функции для выполнения операций параллельно, что позволяет минимизировать использование токенов.

### Ключевые компоненты системы:

1. **Асинхронная обработка данных**:
   - Uses asyncio для выполнения async-функций, что позволяет обрабатывать сообщения не последовательно.
   - Обеспечивает сохранение токенов благодаря промежуточным шагам синхронизации.

2. **Граф обработки (LangGraph)**:
   - Включает sequence of async-функций, выполняемых на разных состояниях графа.
   - Примеры нод: `translate_message`, `judge_role`, `retrieve_rag`, и другие.

3. **База данных**:
   - Формирует акцент на сохранении истории, скорингах моделей, контекста (RAG) и логии.
   - Использует SQLAlchemy для работы с данными, но в асинхронном режиме.

4. **Log management**:
   - Обрабатывает логирование lỗiов и контекстов.
   - Снижает шумosity при обработке сообщений за счет фильтрации и анализа причин ошибок.

5. **Session management**:
   - Создает сессии на основе fixed_llm для пользователя, чтобы сохранять контекст между взаимодействиями.
   - Удаляет сессии после определенного времени без у托чнения.

6. **RAG (Retrieval-Augmented Generation)**:
   - Использует Pinecone или Qdrant для иquotient контекста сообщений.
   - Обновляет векторы контекста после генерации каждого ответа.

7. **LLM (Large Language Model) management**:
   - selects лучшие модели на основе результата скоринга.
   - Поддерживает фиксацию и восстановление сессий для использования оптимальных моделей.

8. **User interface**:
   - Реализует интерфейсы для обработки ввода/вывода, управления падением и чисткой.
   - Позволяет пользователям настраивать систему их потребностями.

### Обработка сообщений:

- **Step 1: Translation**
  - Очищает текст (CLEAN & GPT) -> переводит текст.
  - Внедряет русский текст в базу данных RAG.

- **Step 2: Role determination**:
  - Модель определяет роль текста с использованием логических правил.

- **Step 3: Retrieve related messages (RAG)**:
  - Поиск контекста из предыдущих сообщений.
  - Использует RAG для обработки информации.

- **Step 4: Select appropriate LLM**:
  - Подтверждает ли0, но учитывает сессии пользователя.

- **Step 5: Generate response (LLM)**:
  - Генерирует ответ с использованием selected model.
  - Обновляет сессию и обновляет историю контекста в базе данных.

### Main features:

- Completely asynchronous processing of messages.
- Uses async functions and asyncio under the hood to prevent blocking I/O operations.
- Minimal token consumption due to batch processing and efficient data storage.
- Handles long-term storage (local database) without worrying about resource exhaustion.

The system is designed for efficiency, security, and user-friendliness. It effectively combines translation, role determination, RAG retrieval, and LLM generation in an asynchronous manner to minimize token usage while maintaining high performance.
