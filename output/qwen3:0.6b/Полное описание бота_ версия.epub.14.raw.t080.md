Here's a detailed breakdown of how the bot functions step by step:

---

### **1. Initialization and Setup**
- **Database Initialization**:  
  - Creates tables (`models`, `scores`, `history`, `queue`, `settings`) in `bot.db`.
  - Sets up the RAG system with an embedder (Pinecone/Qdrant) to store message metadata (original text, clean text, author, is_bot).
  
- **LLM Initialization**:  
  - Fetches free LLM models from an API or fallback.
  - Activates models (`db.set_free_llms(models)`) and updates their state (`db.set_model_score(...)`).

- **Graph Creation**:  
  - Builds a workflow with nodes (translate message, judge role, validate role, retrieve rag) and edges for scoring.
  - Handles conditional logic (`needs_rejudge` if "RESCORE").

---

### **2. Message Processing (Telegram Handling)**
- **Message Reception**:  
  - Processes messages using a **threading**-based main loop that runs asynchronously.
- **Blacklist Check**:  
  - If a user is in a blacklist, the message is ignored.  
  - If **paused**, the message is stored but not processed.
- **Clean Message Handling**:  
  - Removes emojis and special characters (`clean_message`).
- **Queue Management**:  
  - Messages are added to the `db.queue` if not processed (via `db.add_to_queue(...)`).
- **Proactive Checks**:  
  - If a user is inactive (due to time), they switch to an **AGITATOR** role.

---

### **3. Graph Processing (LangGraph)**
- **Translation**:  
  - Clean messages are translated and stored in the history and RAG.  
- **Role Validation**:  
  - The LLM determines the role (RESCODE or AGITATOR) based on score and availability.  
- **RAG Retrieval**:  
  - Retrieves the best message context from the RAG and upserts it.  
- **Model Selection**:  
  - Picks the best model from the active or global list.  
- **Proactive Checks**:  
  - If a user is inactive, they are marked as AGITATOR and their message is triggered again.

---

### **4. UI Interaction**
- **UI Elements**:  
  - Sets the message content in the UI (clean, blacklisted, etc.).  
  - Allows users to:
    - **Set clean messages** (removes emojis).
    - **Add blacklists** (marks users as inactive).
    - **Change operators** (determines processing speed).
    - **Toggle PAUSED**.
    - **Reset sessions** (removes fixed LLM models).

---

### **5. Error Handling and Logging**
- **Log Errors**:  
  - Logs exceptions (`log_error(e, context)`) and unused LLMs.
- **Score Storage**:  
  - Stores scores after each model reapplication.
- **Data Persistence**:  
  - Saves all metadata (history, RAG, scores) for message storage.

---

### **6. System Efficiency**
- **Scoring Mechanism**:  
  - Uses a full scoring interval (up to `FULL_SCORING_INTERVAL` messages) for global LLMs.
- **Model Economy**:  
  - Uses top models for sessions (`fixed_llm_{user}`), avoids overusing models (`global_message_count`).
- **Asynchronous**:  
  - Processes messages and updates in parallel using `asyncio`.

### **Key Features and Usage**
- **User Interaction**:  
  - UI controls for managing messages, sessions, and state.
