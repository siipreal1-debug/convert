Объём и фунтовые характеристики сообщения:  
Система реализована в асинхронном потоке (asyncio), что позволяет обработке сообщений параллельно:  
- **Асинхронный цикл**:  
  - Обработка сообщений параллелен.  
  - Независимо от времени обработки одного сообщения.  
- **Экономия токенов**:  
  - Запускает топ- $ N $ модели для обновления в каждом случае.  
  - Сбрасывает $ \text{FIXED}_\text{user} $ модели, если в текущей сессии.  
  - Удалят модели $ \text{FREE}_\text{LLMs} $ за $ \text{MAX}_\text{SCORING_INTERVAL} $.

### Основные этапы обработки сообщений:  
1. **Чистение сообщений**:  
   - Если есть `clean_messages`, используется `clean_message`.  
   - Удаляются лишние символы и эмоджи.

2. **Генерация текста** (например, суммарная в истории):  
   - Устанавливается `RAG.query`, обновляется `history`.  
   - Вся загруженная текст (перевод + суммарное) сохраняется в RAG.

3. **Выбор линуксов** (если в процессе обработки есть `judge_role`):  
   - Выбирается линукс:  
     - `fixed_llm_{user}` — активно сохраняется на сессию.  
     - `global_count` — активно обновляемся на каждые `1` сообщение в `scoring_interval`.  

4. **Проверка на "аварийную" реакцию**:  
   - Если неактивность (инативно), задаётся роль "AGITATOR".  

5. **Параллельная обработка**:  
   - Генерация и проверка обновления (`llm.generate`, `llm.score`, `db.set_model_score`).  

### Адаптация к низкого ресурсного аудиториам:  
- Установка `db.set_free_llms(models)` — сбрасывает `FIXED`, если нет в БД.  
- Менеджмент `session_sessions` и `global_message_count` (счетчик активных сообщений).  

### Программа и установка:  
- Запускается с `pip install -r requirements.txt` и `.env`, с использованием `main_flow.py`.
